3.2 Zip 导出/导入（v4）

需求：旧版导出是单个 JSON 文件，300+MB（照片 Base64 编码），完全没法上传到 GitHub（单文件限制 100MB）。

做法：

  • 引入 JSZip CDN（cdnjs.cloudflare.com/ajax/libs/jszip/3.10.1/jszip.min.js）
  • 重写 exportData()：创建 zip → 写入 manifest.json → 分目录写入每张照片/视频/音乐
  • 重写 importData()：检测扩展名 → .zip 走 JSZip.loadAsync() → 解析 manifest → 用 blob URL 还原
  • 修 bug：accept=".json" → accept=".json,.zip"（之前选文件时看不到 zip）
为什么用 Zip
Zip 里每个文件独立存储，最大单文件 7MB，全部可以正常 push 到 GitHub。旧版 JSON 里 Base64 编码会把 7MB 照片膨胀到约 9MB，300MB 的单文件 push 不了。

3.3 数据推送到 GitHub

需求：把本地 337MB 的备份 zip 也放到 GitHub 上。

尝试 & 失败：

  • 直接用 git push → 超时（文件太大）
  • 用 Git LFS → 推送超时（多次尝试，10 分钟限制）

最终方案：在 GitHub Release 页面用浏览器拖拽上传（浏览器上传比 API 稳定）。Release tag：data-2026-06-01。

3.5 修复自动加载导致的空白页（两次）

第一次修复：两阶段加载

问题：第一版 autoLoadData() 用 Promise.all 等 81 张照片全部下载完（~300MB）才渲染，导致页面空白 2-3 分钟。

修法：改为两阶段——① 文字数据先渲染（< 1 秒）→ ② 媒体文件后台逐个加载，加载完自动刷新视图。加了 15-60s 超时保护。

第二次修复：去掉 localStorage 跳过标记

问题：第一次加载后写了 localStorage.setItem('_momosite_data_ok', '1')，下次刷新看到这个标记就跳过了。但 blob URL 刷新后就过期了，所以第二次打开网站只剩头像。

修法：去掉这个标记。改为每次刷新都重新从服务器加载（加载完的数据存在内存中，不会重复下载）。

现在还有问题吗
用户反馈「还是什么都没有」。说明当前自动加载仍有 bug，正在排查中。可能是 81 张照片的并行 fetch 触发了浏览器连接数限制，或某步抛出异常后整个函数崩溃。详见 常见问题。

3.6 一键更新脚本（update.bat + update.ps1）

需求：用户自己更新数据，不用每次都叫我。

7. 技术细节

7.1 拖拽排序 — 通用函数设计

function initPanelDrag(cfg) {
  // cfg = { id, arr, rfn, attr, sel, onReorder }
  // id:      容器 DOM ID（如 'mpBehaviorList'）
  // arr:     数据数组引用（如 behaviors）
  // rfn:     渲染函数名（如 'renderBehaviors'）
  // attr:    数据属性名（如 'data-bidx'）
  // sel:     可拖拽子元素选择器（如 '.mp-content-item'）
  // onReorder: 可选回调(newArr)，处理 filtered-array 场景
}

使用 Pointer Events API（pointerdown/move/up/cancel），配合 setPointerCapture 保证拖拽时鼠标不会丢失。

├── avatar.png           ← 头像（原始 PNG）

│   ├── beh_0.jpg        ← 行为图鉴第 1 张照片

├── story/
│   └── story_0.jpg

│   ├── photo_0.jpg      ← 81 张相册照片

manifest.json 里的关键字段：

  • behaviors[].photoFile → 照片路径（如 "behaviors/beh_0.jpg"），加载后转为 photoUrl（blob URL）
  • galleryPhotos[].file → 照片路径
  • videoSlots[].file → 视频路径
  • playlist[].file → 音乐路径

7.3 autoLoadData() 工作流

1. fetch('data/manifest.json')
2. 解析 JSON，把文字数据写入全局数组（behaviors、storyItems、rules 等）
3. 立即渲染文字内容（用户看到卡片标题和文字）
4. 逐个 fetch 媒体文件（avatar → behaviors → story → photos → videos → music）
5. 每加载完一个媒体文件，创建 blob URL 并设置到对应元素
6. 全部加载完后重新渲染

加载是串行的（一个接一个），不是并行的。这样避免 81 个并行请求触发浏览器连接数上限（Chrome 限制 6 个/域名），也方便定位哪个文件挂了。

10. 注意事项

10.1 数据安全

  • 每次大改数据前先导出备份。 zip 放桌面就行，这是你的救命稻草。
  • 浏览器清缓存会丢数据。 所以导出 + 推送到 data/ 很重要。
  • data/ 目录是只读快照。 网站不会修改它。只有你导出新 zip 替换才会变。
  • 不要同时用两个浏览器编辑数据。 各自存在各自的 localStorage 里，互相不知道。以最后导出那个为准。

10.2 文件大小限制速查

在哪里限制当前状态
GitHub 仓库单文件100 MB安全 最大 7MB
GitHub Release 单文件2 GB安全 337MB
GitHub Pages 月流量100 GB安全 个人网站用不完
GitHub Pages 站点大小1 GB注意 data/ 约 340MB，有空间但别无限加照片

10.3 绝对不要做的事

  • 不要删 data/ 目录 — 删了别人打开网站就是空的
  • 不要手动编辑 manifest.json — 格式错了网站加载直接报错
  • 不要把旧版 300MB JSON 推送到仓库 — 单文件超 100MB 会 push 失败
  • 不要改 .gitignore — 里面忽略了 momo-backup-*.zip，防止备份文件误入仓库
  • 不要删 .workbuddy/ 文件夹 — 那是项目数据，不是临时缓存

10.4 网站测试技巧

  • 用无痕窗口测试 — 绕过浏览器缓存和 localStorage，模拟别人第一次访问
  • F12 控制台是好朋友 — 所有加载日志都在里面，出问题先看控制台
  • Ctrl+Shift+R 强制刷新 — 普通刷新可能加载缓存版 HTML
