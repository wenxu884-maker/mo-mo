2.2 数据流

网站有三种获取数据的途径，优先级从高到低：

优先级来源说明
1浏览器本地存储用户导入过数据、或在管理后台改过数据（localStorage / IndexedDB）
2data/ 目录自动加载首次访问时从 data/manifest.json 自动拉取所有媒体文件
3默认空数据没有任何数据时的占位状态
关键逻辑
浏览器有数据 → 不用自动加载。 只有首次访问（或清过缓存）才触发自动加载。加载完成后 localStorage 写入 _momosite_data_ok=1，下次跳过。

2.3 导出/导入格式

版本格式说明
v4（当前）Zip 压缩包每个媒体文件独立，单文件 < 7MB，适合 GitHub 仓库
v3（旧版）单 JSON 文件Base64 内嵌，几百 MB 无法上传 GitHub，仅作兼容保留

导入时自动识别格式：.zip 走 Zip 导入，.json 走旧版导入。

3. 今天完成的操作

3.1 拖拽排序 — 全 5 个面板

修改内容： 将原来只支持「使用须知」的硬编码拖拽函数，重构为通用函数 initPanelDrag(cfg)，然后应用到全部 5 个面板。

面板数据数组选择器
行为图鉴behaviors[].mp-content-item，data-bidx
使用须知rules[].mp-content-item，data-ridx
相册集galleryPhotos[].mp-file-item，data-pidx
文具专题storyItems[].mp-content-item，data-sidx
影像档案videoSlots[].mp-file-item，data-vidx，带 onReorder 回调
技术要点
initPanelDrag(cfg) 接收配置对象 {id, arr, rfn, attr, sel, onReorder}。其中 onReorder 是可选回调，用于影像档案这种 filtered-array 需要自定义重排逻辑的场景。

3.2 Zip 导出/导入 v4

修改内容：

  • 引入 JSZip CDN：cdnjs.cloudflare.com/ajax/libs/jszip/3.10.1/jszip.min.js
  • exportData() 重写：创建 zip，内含 manifest.json + 各媒体文件夹（behaviors/、story/、photos/、videos/、music/、avatar.png）
  • importData() 重写：检测 .zip 扩展名 → JSZip.loadAsync() → 解析 manifest → 用 blob URL 还原所有文件
  • 文件选择器 accept=".json,.zip"（之前只接受 .json 导致 zip 选不上）
已知问题及修复
最初 accept=".json" 只接受 JSON 文件，导致浏览器文件选择器中无法选中 .zip 文件。已改为 accept=".json,.zip"。

3.3 数据自动加载

修改内容： 新增 autoLoadData() 函数，首次访问时自动从 data/ 目录加载所有数据。

两阶段加载：

阶段内容耗时
① 立即默认空数据渲染（占位卡片）< 100ms
② 文字重渲染manifest.json 加载 → 文字数据替换 → 重新渲染面板< 1s
③ 媒体后台加载照片/视频/音乐逐个下载，下载完自动刷新视图~30s（不阻塞使用）
修复记录
第一版 autoLoadData() 是用 Promise.all 等 81 张照片全部下载完才渲染，导致页面空白 2~3 分钟。已改为两阶段：文字数据先渲染，媒体文件后台加载，超时保护 15~60s。

6. 常见问题排查

🔴 网站打开是空白的

可能原因解决方法
自动加载正在下载 300MB 的照片（后台进行中） 等 30 秒 ~ 1 分钟。控制台会显示「📦 加载进度」。已经渲染过文字内容就应该有字，如果字也没有 → 看下一条
JS 加载报错，某张照片加载失败阻塞了渲染 打开 F12 控制台看报错。已加了超时和错误处理，单张照片失败不影响其他
GitHub Pages 还没部署完成 等 1~2 分钟刷新。如果超过 5 分钟，去 GitHub Actions 看部署状态
浏览器缓存了旧版 HTML Ctrl+Shift+R 强制刷新，或用无痕窗口测试

🔴 照片不显示（占位框但没有图片）

可能原因解决方法
照片还在下载中 看控制台有没有「📦 加载进度」。小照片几秒，大照片十几秒
data/ 目录里缺少这张照片 可能是导出时遗漏或路径不匹配。重新导出 zip 并替换 data/
文件名编码问题 确认 manifest.json 里的路径和实际文件名一致

🔴 git push 失败

可能原因解决方法
网络问题 重试。如果连续失败，换 VPN 或等网络恢复
单个文件超过 100MB 把大文件拆小，或放到 GitHub Release（我知道哪些文件大，告诉我路径即可）
冲突（别人也 push 了） git pull --rebase 然后重试 push

🔴 导入 zip 没反应

可能原因解决方法
zip 文件损坏 重新导出一次
zip 里缺少 manifest.json 确认是用网站的「导出数据」按钮生成的 zip，不是自己打包的
浏览器不支持 JSZip 极少数情况。换 Chrome/Edge 试试

🔴 想回到某个时间点的数据状态

GitHub Release 的 Assets 里有多份历史备份 zip。下载对应日期的 zip → 网站上点「导入数据」→ 恢复。

7. 注意事项

7.1 数据安全

  • 每次大改数据前先导出备份，zip 文件放在桌面上就行
  • 浏览器清理缓存会丢失数据，所以导出 + 推送到 data/ 很重要
  • data/ 目录就是一个只读快照，网站不会修改它——只有你导出新 zip 替换它才会变

7.2 文件大小限制

位置限制备注
GitHub 仓库单文件100 MB超出会 push 失败。当前所有文件 < 7MB，安全
GitHub Release2 GB备份 zip 的存放上限
GitHub Pages 带宽100 GB/月个人网站够用了

7.3 不要做这些事

  • 不要删 data/ 目录 — 删了别人打开网站就是空的
  • 不要手动编辑 manifest.json — 它是导出时自动生成的，格式错了网站加载会失败
  • 不要把 300MB 的旧版 JSON 推送到仓库 — 会导致 push 失败。用 zip 格式
  • 不要改 .gitignore 里的 momo-backup-*.zip — 防止大量备份文件进入仓库
  • 不要同时用两个浏览器编辑数据 — 数据存在各自的 localStorage 里，不会同步，最终以你导出那个为准
